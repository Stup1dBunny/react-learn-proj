## О проекте

============

**Покедекс** — это веб-приложение для поиска и просмотра информации о покемонах.
Проект создан для демонстрации владения современным стеком React и навыков
разработки SPA с акцентом на производительность, UX и чистоту кода.

========================

### Ключевые возможности

========================

| Фича                  | Описание                                                  |
| --------------------- | --------------------------------------------------------- |
| **Фильтрация**        | Поиск по номеру, имени или типу — мгновенный результат    |
| **Пагинация**         | 20 карточек на страницу с навигацией                      |
| **Кэширование**       | Данные хранятся 5 минут, повторные запросы не грузят API  |
| **Адаптивность**      | От 5 колонок на десктопе до 1 на телефоне                 |
| **Оптимизация**       | React.memo + useCallback + useMemo против лишних рендеров |
| **Skeleton-загрузка** | Плавное появление контента вместо пустого экрана          |
| **Работа с API**      | Параллельные запросы + автоматический retry при ошибках   |

## Почему я сделал так, а не иначе

==================================

### 1. Фильтрация — кастомный хук + useMemo

**Проблема:** Нужно было фильтровать по трём параметрам (номер, имя, тип) без потери производительности.  
**Решение:** Создал кастомный хук `usePokemonFilter`, который принимает все три параметра. Логику фильтрации обернул в `useMemo`, чтобы пересчёт происходил только при реальном изменении значений в инпутах.  
**Результат:** Фильтры работают мгновенно, без лишних рендеров.

### 2. Кэширование — React Query

**Проблема:** При каждом переходе на страницу карточек данные загружались заново, создавая лишнюю нагрузку на API.  
**Решение:** Использовал React Query с `staleTime: 5 минут`. Добавил `retry: 3` и экспоненциальную задержку, чтобы при ошибках запрос автоматически повторялся.  
**Результат:** Данные не перезагружаются без необходимости, а при проблемах с сетью приложение пытается восстановиться само.

### 3. Адаптивность — CSS Grid + медиа-запросы

**Проблема:** На телефонах карточки ломались или выглядели плохо.  
**Решение:** Использовал CSS Grid с фиксированным количеством колонок для разных брейкпоинтов: 5 → 4 → 3 → 2 → 1.  
**Результат:** Сайт одинаково хорошо выглядит на любом устройстве.

### 4. Оптимизация — React.memo + useCallback + useMemo

**Проблема:** При фильтрации или смене страницы перерендеривались все карточки, что замедляло работу.  
**Решение:** Обернул карточки и модалку в `React.memo`, функции-обработчики — в `useCallback`, пагинированные данные — в `useMemo`.  
**Результат:** Перерендер только того, что действительно изменилось.

### 5. Skeleton-загрузка — вместо "Загрузка..."

**Проблема:** Пользователь видит пустой экран или надпись "Загрузка...", что создаёт ощущение медлительности.  
**Решение:** Добавил скелетоны — карточки-заглушки, которые повторяют форму реальных карточек.  
**Результат:** Пользователь сразу видит структуру страницы, а реальные карточки подгружаются плавно.
